# Version 1 acceptance matrix

This matrix tracks the 23 product criteria required before the first stable core release. It
separates deterministic repository evidence, recorded real-browser fixture evidence, and the
remaining manual and publication work.

Use the [documentation map](README.md) for recipes, operational guides, API references, troubleshooting, and architecture decisions.

Status meanings:

- **Automated:** covered by the required Node-based repository gates.
- **Operator:** covered by the recorded real-browser fixture matrix.
- **Operator pending:** required manual application, asset-hosting, or physical-device evidence remains
  open.
- **Release pending:** implementation and package validation exist, but completion depends on the
  release process.

The project does not claim a stable v1 while any operator or release item remains pending.

## Release boundary

Stage 8 integrated the browser suite. Chromium and Firefox passed all 14 scenarios on Windows;
Windows WebKit passed nine scenarios with five platform-qualified media-presentation skips; and
[Dwayne Samuels](https://github.com/DwayneSamuels) subsequently passed all 14 WebKit scenarios on
macOS 14.6.1 Intel. The [validation record](browser-validation-results.md) preserves the exact
revisions, environment, frozen-WebKit warning, and claim boundaries.

The automated browser baseline is complete, but it does not imply branded Safari, current WebKit,
Apple silicon, every production encoding, or every device. Stable `1.0.0` remains gated by the
manual supplement, release-candidate feedback including
[#32](https://github.com/mariozenmedina/frame-by-frame/issues/32), and the remaining release
process. Criterion 1 becomes complete only after the stable package is published and independently
installable.
